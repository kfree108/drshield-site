What the Case Log actually is

The Case Log is Seller Central's running record of every ticket you have opened, or that has been opened on your account: a support request, a reimbursement claim, a suspension appeal, a fee dispute. Each gets a case ID, a status and a message thread with Amazon. For anything that needs evidence or follow-up, it is effectively the file the reviewer works from, so how you use it is part of how well a case gets resolved.

Every message you send inside a case becomes part of that case's record. A clear, evidence-backed message strengthens the file each time you add one. A "why hasn't this been resolved yet" message with no new information adds nothing, and several of them in a row only make the thread longer for the next reviewer to read.

The rule that matters most: one case ID per issue

The highest-leverage habit is keeping exactly one case ID open per distinct issue. Opening a second case for the same problem, because the first felt slow or another rep might answer faster, splits your evidence and history across two threads that reviewers may not connect. If a case needs escalation, escalate that same case ID rather than starting over.

The flip side matters too: two related but different problems, such as a reimbursement claim and a fee dispute on the same shipment, are still two case IDs. Keep them separate so each can be decided on its own evidence.

Our own claim data shows why this matters. Across the seller accounts we manage, we recovered $803,457 net from Amazon between 10 Feb and 21 Aug 2026 (from $973,504 gross, less $170,047 in reversals). That was 42,096 line items across 1,033 distinct cases, which works out to about 41 line items per case on average. Claims are filed in batches under a single case ID, so one fragmented or abandoned case can put a lot of line items at risk at once.

A worked example of managing parallel cases

Take an account running normal volume with three open cases at once: a reimbursement claim for lost inventory, a fee dispute over a dimension remeasurement, and a listing suppression appeal. Managed well, each has its own case ID, a note of what evidence was submitted and when, and a follow-up date. Managed poorly, the same three issues become six or seven case IDs because a slow reply on one prompted a duplicate, and now the same reimbursement claim is competing with itself for review.

A simple external log, in a spreadsheet or whatever ticketing tool you already use, turns this from a memory exercise into a checklist. Use these columns:

  • Case ID and a one-line description of the issue
  • Type: reimbursement, fee dispute, appeal, listing, other
  • Filed date and the deadline for filing or responding, if the case type has one
  • Evidence attached: invoices, shipment IDs, photos, with dates sent
  • Next action and next follow-up date

Reading case status correctly

A case in an open status such as "Amazon is investigating" is not necessarily stalled. Response times vary by case type and volume, and Amazon does not publish a fixed service level for most categories. What is worth tracking is elapsed time against what similar cases on your own account have taken, not against a published deadline that does not exist. If a case has gone quiet well past your own norm, follow up on the existing case ID with something new, such as an extra document or a clarified date, rather than "any update?"

Read status labels literally rather than emotionally. "Awaiting your response" means the ball is in your court and the case will not move until you act; checking for it daily costs nothing and can save days. "Under review" means Amazon has what it needs and the delay is on its side; following up here adds noise without changing the timeline.

The common mistake: treating the log as a mailbox instead of a file

The mistake we see most is checking the Case Log reactively, only when a notification arrives, rather than maintaining it as a working file with next actions and dates. A reimbursement claim that needs a follow-up at a set date, or a dispute that needs a document that was not ready at filing, both need someone tracking them forward. On accounts running several cases, that gap is usually where cases lose momentum or run past a filing window, rather than a decision Amazon made against the seller.

Here is the arithmetic, as a worked example. If a claim has a 60-day window and sits unchecked in the Case Log for 45 days, only 15 days remain to gather evidence and file correctly. The same claim checked weekly from the day the loss was found has the whole window. Check the actual window for your case type in Seller Central, because it differs by claim type. The Case Log does not enforce that discipline; it only records whatever discipline you bring.

A weekly review checklist

Fifteen minutes once a week keeps most accounts out of trouble:

  • Open the Case Log and filter to open cases. Match each one to a row in your tracker; add any that are missing.
  • Answer every case showing "Awaiting your response" first.
  • For each case past its follow-up date, add one new piece of information to the existing case ID. Never open a second case.
  • Check the deadline column for anything inside two weeks and gather the evidence now.
  • Close out resolved cases in your tracker, noting the outcome so you can see what each case type usually takes.

If you find a duplicate you opened by accident, reference the original case ID in it and ask for the two to be merged or the duplicate closed.

Common questions

Should I open a new case if my current one is taking too long?

No. Follow up on the existing case ID with new relevant information. A second case for the same issue splits your evidence across two threads and makes both harder to review.

How do I know if an Amazon case is actually stalled?

Amazon does not publish a fixed response time for most case types, so compare against how long similar cases on your own account have taken. Meaningfully longer than usual is worth a follow-up; a few extra days usually is not.

Can I track multiple open cases in one place?

The Case Log lists every open and closed case with its ID and status, but it does not prompt follow-up actions. Keep a separate tracker with case ID, type, filed date, deadline and next action if you run several cases at once.

What happens if I accidentally open a duplicate case?

Reference the original case ID in the duplicate and ask that it be merged or closed in favor of the first. Leaving both open and unattended is what causes confusion and delay.

Should I keep my own record of cases outside Seller Central?

Yes, once you have more than a couple of open cases. An external tracker catches expiring windows and unanswered requests that the Case Log will not flag for you.
